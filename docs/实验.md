# 阅读&重配训练代码流程
## 预训练
### reference构建
克隆仓库预训练的合成data和我们已有设备的lora frame格式有所差异，因此构建GT(reference）不可复用已有合成PHY逻辑

```python
RF-SR 预训练：
[DST][SRC][SEQNO][LENGTH] + 16-byte 随机数据
         自定义4字节头         

我们使用的STM32：
[MHDR][DevAddr][FCtrl][FCnt][FPort] + 20-byte数据 + MIC
                  总共33字节
```

:::info
本质上**OTA就是模型的输入x，而reference和metadata相当于是标签**，但是这样就有了另一个问题，微调的时候只有若干种payload的话，学到的映射关系难道就不会导致输入不管是什么都会映射到一个符号上吗？

也就是说，正常解码工作流程中，没有见过的payload可能也会强行映射，这一点需要验证！

**<font style="color:#000000;background-color:#FBDE28;">所以目前为了解决这个问题，选择在合成数据预训练的时候完全payload随机生成！（但是只在启动的时候随机即可）</font>**

:::

从高亮块中可以看出预训练时，合成数据payload随机性的重要性，并且大概率在真实数据微调过程中数据量不宜过大。（这么小一个模型有必要pretrain+finetune吗？)

```python
完整预训练命令是：

  cd /root/lora-rfsr-savaux/third_party/rfsr

  PYTHONPATH=. python -u rfsr/nn/nn.py \
    --model model0v0 \
    --batch_size 5 \
    --osf 4 \
    --dsf 8 \
    --dataset_size 250 \
    --num_epochs 100 \
    --synthetic-source reference_phy \
    --reference-root /root/lora-rfsr-savaux/data/reference_phy \
    --synthetic-seed 42 \
    --snr-min-db -22 \
    --snr-max-db 10 \
    --cfo-min-hz -35000 \
    --cfo-max-hz 35000 \
    --sto-initial-min-chips -0.5 \
    --sto-initial-max-chips 0.5 \
    --sto-slope-min-chips-per-symbol -0.05 \
    --sto-slope-max-chips-per-symbol 0.05
```

### pretrain流程
```python
packet_reference.txt
→ 已生成的 metadata
→ 读取 PHY 参数和 frame_bytes=33（只读这些，并不包含payload符号具体内容）
→ 每次 __getitem__ 随机生成全新 33-byte raw payload
→ explicit header
→ whitening
→ grlora PHY CRC
→ Hamming
→ interleaving
→ Gray mapping
→ LoRa chirp IQ
→ 得到 clean y：1 MSPS，[2, 2770704]
→ y 每4点抽1点：250 kSPS
→ 按指定 SNR 给低采样输入添加 AWGN，并且单独给x加入随机的CFO
→ 得到 noisy x：[2, 692676]
→ RF-SR 插值 + 四层残差 CNN
→ 预测 1 MSPS IQ，与 clean y 计算损失
```

当前 explicit PHY header 包含：

```plain
Payload Length：8 bit
Coding Rate：3 bit
Payload CRC Enable：1 bit
Header Checksum：5 bit
保留/填充：3 bit
```

预训练过程除了**PHY数据要和微调对齐**外，还值得注意的就是**SNR的配置**

:::info
此外考虑到只加CFO或许有些不符合真实的lora接收场景，因此加入STO的建模:

+ 每包随机 `τ₀ ∈ [-0.5, 0.5] chip`。
+ 随机斜率 `[-0.05, 0.05] chip/symbol`。
+ 按 `τ_s = τ₀ + s·slope` 变化，对应 `ζ=-slope/(2^SF-1)`。
+ 直接执行 `i → i-τ_s` 分数采样，而非重复叠加相位补丁。
+ 自动产生 `f_s≈-τ_s`、符号相关相位和 chirp 回绕两侧的相位跳变。
+ 处理顺序为：`ideal y → STO采样 → CFO → AWGN → x`。

:::

#### RFSR微调
所以合成数据预训练的流程是，**先生成高采样（目标采样）数据作为标签，然后降采样作为输入**

**配置**

+ 模型：model0v0，12,802 个参数
+ 数据：250 个合成完整 LoRa packet
+ PHY：**SF12、BW 125 kHz、-byte payload、8-symbol preamble、显式头、CRC 开启、代码参数 cr=4**
+ SNR：每包从 [-22, 10] dB 均匀采样
+ **输入采样率：250 kSPS**
+ **输出采样率：1 MSPS**
+ 升采样倍率：OSF=4
+ Batch size：5 个完整 packet
+ Epoch：100，每个 epoch 50 batches
+ 优化器：Adam
+ 学习率：1e-3
+ Weight decay：1e-5
+ Loss：MSE
+ 梯度裁剪：max_norm=1.0

**本次结果**

+ 首轮 loss：0.6251728
+ 最终 loss：0.2799376
+ 最低 loss：0.2790464（epoch 98）
+ 显存占用：约 12.7 GB

**数据生成特点**

+ 每个样本是完整 packet，不是单个符号。
+ 250 个 packet 在训练启动时一次性生成并缓存。
+ 100 个 epoch 重复使用同一批 packet、SNR 和噪声，只改变 shuffle 顺序。
+ 输入由干净高采样率标签每 4 点抽取一次，再添加 AWGN。

#### 现在
不收敛啊我靠，是数据的原因 还是SFOSTO的原因?

| 扰动 | 6 轮最低 loss |
| --- | ---: |
| 全关：CFO = 0、STO/SFO = 0 | 0.3984 |
| 只有初始 STO | 0.4189 |
| 只有 SFO 斜率 | 0.5272 |
| STO + SFO | 0.5267 |
| 只有 CFO | 0.5172 |


结论比较明确：初始 STO 不是主要问题，SFO 斜率明显阻碍收敛，CFO 也有同等级影响。

原因是 `model0v0` 的四层 `kernel_size=3` CNN 感受野只有 9 个高采样率点。初始 STO 最大为 $ \pm0.5\ \text{chip} $，对应 $ 1\ \text{MHz} $ 下约 $ \pm4 $ 点，勉强在感受野范围内；SFO 默认每个符号漂移 $ \pm0.05\ \text{chip} $，整包末端可以积累到约 $ \pm4.2\ \text{chip} $，也就是约 $ \pm33 $ 点，远超模型感受野。

与此同时，`lora-rfsr-savaux/third_party/rfsr/rfsr/nn/dataset.py:390` 中，输入加入了 STO、SFO 和 CFO，标签却始终保持零偏移，相当于要求这个浅层局部 CNN 同时完成整包同步补偿和超分辨率。它做不到是合理的。

建议先保留初始 STO，关闭 SFO 和 CFO：

```bash
--cfo-hz 0 \
--sto-slope-min-chips-per-symbol 0 \
--sto-slope-max-chips-per-symbol 0
```

**要严格复现无扰动基线，则使用：**

```bash
--cfo-hz 0 --no-sto
```

当前 `--no-sto` 会同时关闭初始 STO 和 SFO 斜率；代码中没有单独的 `--no-sfo`，将 slope 的上下限都设为 0 即可。以及原版的样本是反复使用的，不是每训练一个epoch就生成一个新的

## 采集数据微调
### 数据集内容与文件结构
AppTxDataBuffer        = 20字节应用数据

LoRaMacBuffer/Radio.Send = 33字节实际发送数据

以及为了数据集可以覆盖更多的情况，STM32工程代码编写逻辑：**循环发送120种确定性伪随机payload，ID为0–119**。前2字节保存小端`payload_id`，后18字节由固定seed生成伪随机数据。第121包重新回到ID 0，内容完全一致，便于复用clean reference。MCU重启后从ID 0重新开始，保持应用payload 20字节、最终`Radio.Send()` 33字节不变。

### 映射规则
1. 采集真实的高采样率IQ，然后降采样形成OTA，这些采集到的高采样率IQ就作为reference：

“高 SNR 实采 IQ → 直接降采样配对”只适合辅助实验。它的 `y` 仍保留真实 CFO、STO、信道和噪声，模型学习的是纯升采样并保留这些失真；这与我们当前“`x` 有 CFO/STO，`y` 是理想零 CFO/STO”的预训练目标不一致。  

2. 已知 payload/packet ID 发射，采集宽 SNR 的真实 2 MSPS OTA IQ，OTA 降采样到 250 kSPS，作为 x。**按已知 payload 生成理想 reference，裁剪并对齐到 1 MSPS，作为 y**，这个貌似和我们的预训练会更贴。

目前主要是调通整个流程，因此这一块儿先选择2.

# 跑通
## pretrain
目前给RFSR加入的一些新的元素：SFO，STO，CFO以及预训练启动时dataloader会随机生成一组数据用来训练。包含了这些不稳定因素导致目前预训练收敛情况较差：

+ **一个原因就是感受野太小，学不到SFO STO引起的若干采样点的变化。**

于是这次就把CFO SFO STO这些都关掉进行预训练：（但是payload依旧随机变化）

```python
cd /root/autodl-tmp/rfsr-run/pretrain

  export PYTHONPATH=/root/lora-rfsr-savaux/third_party/rfsr

  python -B /root/lora-rfsr-savaux/third_party/rfsr/rfsr/nn/nn.py \
    --model model0v0 \
    --batch_size 5 \
    --osf 4 \
    --dsf 8 \
    --dataset_size 250 \
    --num_epochs 100 \
    --learning_rate 0.001 \
    --weight_decay 1e-5 \
    --optimizer adam \
    --synthetic-source reference_phy \
    --reference-root /root/lora-rfsr-savaux/data/reference_phy \
    --synthetic-seed 42 \
    --snr-min-db -22 \
    --snr-max-db 10 \
    --cfo-hz 0	 --no-sto
```

这次是一个“先把基础插值/去噪能力学稳”的合成预训练消融实验：保留 payload 与 AWGN 的变化，但关闭 CFO 和采样时序扰动，降低任务难度。

配置可以概括为：

+ **模型**：`model0v0`，四层复数残差 CNN 加 polyphase interpolation；未带 `hl` 等后缀，因此损失函数为默认 MSE。
+ **采样率**：输入 $ 250\ \mathrm{kS/s} $，输出及标签为 $ 1\ \mathrm{MS/s} $，即使用 `--osf 4` 实现 $ 4 $ 倍超分辨率。`--dsf 8` 与原始 $ 2\ \mathrm{MS/s} $ 到 $ 250\ \mathrm{kS/s} $ 的关系保持一致。
+ **数据**：从 `reference_phy` 的 metadata 中读取 LoRa PHY 参数，每次启动时生成并缓存 $ 250 $ 条合成样本。每条样本都包含随机 raw payload，标签为理想的 $ 1\ \mathrm{MS/s} $ LoRa 波形。
+ **随机性**：`--synthetic-seed 42` 固定，因此这 $ 250 $ 个 payload、SNR 和 AWGN 样本在每次启动时均可复现；训练中的每个 epoch 只改变 DataLoader 的读取顺序，不会重新生成波形。
+ **保留的扰动**：输入中仍然加入 SNR 均匀分布在 $ -22\sim10\ \mathrm{dB} $ 范围内的 AWGN。
+ **关闭的扰动**：`--cfo-hz 0` 将 CFO 固定为 $ 0 $；`--no-sto` 同时将初始 STO 和逐符号 STO 斜率归零，后者对应 SFO 式采样时钟漂移。
+ **优化配置**：Adam，`batch_size=5`，学习率为 $ 10^{-3} $，weight decay 为 $ 10^{-5} $，最多训练 $ 100 $ 个 epoch。未显式设置 early stopping，因此默认在训练损失连续 $ 10 $ 个 epoch 未改善时停止。

实验流程为：

1. 校验 `reference_phy` metadata 中的 PHY 配置，并创建 $ 250 $ 个预训练样本。因此日志中首先出现 `Dataset size: 250`，随后每生成 $ 10 $ 条样本打印一次 `Added: ...`。
2. 对每条样本使用随机 payload 编码生成干净的 $ 1\ \mathrm{MS/s} $ 标签 $ \mathbf{y} $。
3. 对标签进行 $ 4 $ 倍降采样，构造低采样率输入 $ \mathbf{x} $；不施加 CFO、STO 和 SFO，但加入随机 SNR 的 AWGN。
4. 使用固定的 $ 250 $ 对 $ (\mathbf{x},\mathbf{y}) $ 反复训练，每个 epoch 仅对样本顺序进行 shuffle。
5. 在当前目录写出 checkpoint 和训练 loss 历史，例如当前已有的 `bs5` 权重文件。

这次实验测量的是：

> 在随机 payload 和不同噪声强度下，模型能否先稳定学习“$ 250\ \mathrm{kS/s} $ 有噪输入 $ \rightarrow 1\ \mathrm{MS/s} $ 理想波形”的基础映射，而不要求它同时补偿长时间尺度的 CFO、STO 和 SFO 变化。
>

这次微调是在“真实接收波形的严格 RF-SR”设定下，把预训练模型适配到 OTA 噪声、实际包边界和采样相位。

首先需要区分两件事：

+ 数据制作时，OTA 包必须按 reference 的时间轴和长度对齐。reference 在 $ 1\ \mathrm{MS/s} $ 前置了 $ 10{,}000 $ 个零，因此 builder 从原始 $ 2\ \mathrm{MS/s} $ 捕获中，在检测到的 preamble 前取 $ 20{,}000 $ 个真实采样点；降到 $ 1\ \mathrm{MS/s} $ 后，OTA 文件前面保留 $ 10{,}000 $ 个真实的 off-packet 噪声采样点，低采样输入中就是 $ 2{,}500 $ 点。它们不是给 OTA 人为补的零，而是保留下来的真实环境噪声。
+ 训练时，设置的是 `--ota-target received`。因此模型监督目标是同一段真实 $ 1\ \mathrm{MS/s} $ OTA 波形，不是理想 reference。reference 在这里承担包关联、裁切长度和时间原点的锚点；不会进入 loss 作为标签。若改为 `--ota-target reference`，才是“接收 OTA $ \rightarrow $ 理想 reference”的另一种任务。

微调流程是：

1. 从连续 $ 2\ \mathrm{MS/s} $ 采集中检测并确认物理包，按 reference 的 $ 1\ \mathrm{MS/s} $ 长度裁切；每包拆成两个 ADC 相位的 $ 1\ \mathrm{MS/s} $ OTA 文件。
2. 每个 $ 1\ \mathrm{MS/s} $ 文件取四种 $ 250\ \mathrm{kS/s} $ polyphase，相当于每个物理包生成 $ 8 $ 个高度相关的 view。每个 view 的长度是 $ 692{,}676 $ 点，目标为 $ 2{,}770{,}704 $ 点，严格保持 $ 4:1 $。
3. 由 seed `42` 稳定地从 $ 129 $ 个物理包**抽取 **$ 24 $** （少了）个**，按物理包划为训练 $ 14 $ 包/$ 112 $ views、验证 $ 5 $ 包/$ 40 $ views、测试 $ 5 $ 包/$ 40 $ views，防止相同包的不同相位泄漏到不同集合。
4. 加载 `model0v0` 的合成预训练权重；`model0v0hl` 沿用相同网络结构，但启用适合 OTA 的时域 L1 + FFT 幅度 L1 混合损失。
5. 以 batch size `1`、学习率 $ 10^{-4} $、Adam 做最多 $ 100 $ 个 epoch 的微调；验证损失连续 $ 10 $ 个 epoch 不改善时停止，并保存验证集最佳权重。

## 损失函数：先做有文献依据的最小消融

先确定一个前提：loss 不能补救错误的标签对齐。NELoRa 明确指出，随机的 symbol timing/CFO 会造成频谱平移并误导网络，训练样本应先完成时间与频偏对齐。因此使用 ideal reference 作标签时，必须先消除 `x/y` 之间不希望网络学习的 CFO、STO 和全局复增益差。

现阶段只比较三组，不先堆复杂 loss：

1. `L_time = MSE(pred_IQ, target_IQ)`：作为干净基线，同时删除 `lopenalty` 的参数 L1，只保留 `weight_decay`。
2. `L_time + λ_spec L_spec`：参考 LoRaSeek，联合优化时域 IQ MSE 和 symbol 级 spectrogram MSE；不用当前的整包、未归一化 FFT 幅度 L1。
3. `L_time + λ_spec L_spec + λ_sym CE`：参考 NELoRa，在可微的 dechirp+FFT 后对真值 symbol bin 加交叉熵，把训练目标直接绑定到 SER。

实验顺序为 `1 → 2 → 3`；每次只新增一项，并同时记录 validation waveform loss、同步成功率和条件 SER。若第 2 组无收益，就不继续引入更复杂的 multi-resolution STFT；若第 3 组降低 SER，再讨论它的权重和适用 symbol 区间。

依据：

- [NELoRa, SenSys 2021](https://mi-zhang.github.io/papers/2021_SenSys_NELoRa.pdf)：联合 spectrogram MSE 与 symbol cross-entropy，并强调训练前的 timing/CFO 对齐。
- [LoRaSeek, MobiCom 2025](https://cse.msu.edu/~caozc/papers/mobicom25-khang.pdf)：使用 spectrogram MSE + time-domain MSE 的双重重建损失，并采用从高 SNR 到低 SNR 的 curriculum learning。
- [Parallel WaveGAN, ICASSP 2020](https://arxiv.org/abs/1910.11480)：波形重建中 multi-resolution STFT 优于单一频谱尺度，可作为第 2 组之后的备选，而不是第一步。
