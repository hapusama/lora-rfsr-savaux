## 1. 当前研究目标

主问题是判断 RF-SR 将 250 kSPS LoRa IQ 恢复到 1 MSPS 后，能否为 Savaux 多 offset 分支提供新增的有效观测，而不仅仅是重复 RF-SR 本身的插值/去噪收益。

正式比较必须包含：

```text
A  原生 250 kSPS -> 普通 LoRa
B  原生 250 kSPS -> 作者精确 polyphase interpolation -> Savaux
C  原生 250 kSPS -> RF-SR -> 普通 LoRa
D  原生 250 kSPS -> RF-SR -> Savaux + branch GLS
E  原生 ADC 1 MSPS -> Savaux
```

最关键的消融仍是：

```text
B：纯插值 + Savaux
vs.
D：RF-SR + Savaux
```

必须使用同一个低速率数组作为 B/D 的输入，并固定 packet、同步、CFO、STO、SNR 和噪声 realization。

错误被拆成：

```text

  低采样混叠 bin 正确，但 alias group 选错

wrong_alias_bin:
  连混叠后的 modulo-256 bin 都错
```

跨完整 SNR 网格：

| 方法 | 总错误 | wrong_group | wrong_alias_bin | alias-bin 错误占比 |
|---|---:|---:|---:|---:|
| K1 | 18,144 | 767 | 17,377 | 95.77% |
| K2 | 10,617 | 200 | 10,417 | 98.12% |

结论：主要问题不是 group fingerprint，而是 coarse aliased-bin 本身已被噪声峰选错。即使 oracle 修复全部 wrong_group，SER 下界仍接近当前结果。后续若继续 LiteNap，应优先提升 alias-bin 可靠性（更多相干能量、重复 symbol/packet combining 或 codec-aware soft likelihood），不应继续只优化 group 分类器。

`model0v0` 有 12,802 个可训练参数。处理流程为：

```text
250 kSPS [B,2,L]
  -> 作者 Kaiser-windowed sinc polyphase ×4
  -> 1 MSPS [B,2,4L]
  -> 四层 1-D CNN，complex-channel 1->16->32->16->1
  -> CNN residual + interpolation
  -> 1 MSPS [B,2,4L]
```

CNN 四层均为 kernel=3、padding=1，前三层 ReLU。CNN 自身高采样率感受野只有 9 samples；插值 FIR 是主要边界上下文（配置 width=511，实际支持约 512/513 taps）。因此“整包巨大输入”是当前 dataset/training interface 的选择，不是 CNN 必须看到整包全局上下文。

## 4. Synthetic 预训练数据的准确含义

入口：

```text
RFSuperResolution/rfsr/nn/nn.py
RFSuperResolution/rfsr/nn/dataset.py::SyntheticLoRaDataset
```

默认论文参数下，每个样本：

```text
y: 1 MSPS clean IQ，float32 [2, 1,722,228]
x: y[::4] 后加 AWGN，250 kSPS，float32 [2, 430,557]
snr: [-22, +10] dB 的一个标量
```

每个 dataset item 随机 16-byte payload、SNR 和 AWGN。固定项包括 SF/BW、起始相位、timing fraction 和代码中的 CFO 模型。`dataset_size=250` 会在 `__init__` 中一次生成并缓存 250 个固定样本；100 epochs 只重排并重复读取，不会每 epoch 重新加噪。

`PHY.py` 在 1 MSPS 标签前放 10,000 个理想零点（10 ms）。降采样后，x 中对应 2,500 点也是 10 ms；AWGN 加到整个 x 后，该段成为“纯 AWGN 输入 -> 零标签”。这只训练了高斯 off-packet 静默，不代表真实非高斯环境噪声。

已发现但未修复的小问题：`input_len/output_len` 用单独的 250 kSPS encode 估算，而 `p_ofs=10000` 是固定样点数而不是固定时间，导致字段值与实际 `x/y` 长度不一致；这两个字段当前没有参与训练切片。

## 5. OTA 微调数据契约

公开 loader 使用无头一维 NumPy `complex64` 文件：

```text
每个复样点 = float32 I + float32 Q = 8 bytes
```

`.cfile` 和 `.bin` 都只是扩展名；真实格式由 producer 和 `dtype` 决定。SC16 是 `int16 I + int16 Q`（4 bytes/complex sample），不能被 `np.fromfile(..., dtype=np.complex64)` 直接解释，必须先数值转换和归一化。

代码可推断的作者目录/命名意图：

```text
rfsr/nn/data/post/
  exp1_000020_rxg18_0_fulltrim.cfile    # 2 MSPS noisy OTA RX
  signalout_000020_fulltrim.cfile       # 2 MSPS paired reference/GT
```

默认 DSF=8、OSF=4：

```text
rx 2 MSPS  -> [::8] -> x = 250 kSPS [2,L]
ref 2 MSPS -> [::2] -> y =   1 MSPS [2,4L]
```

“同一个 packet”不是仅有相同 SF/BW，而是 x/y 必须编码相同 payload、header、sequence、CRC 和 LoRa symbol 序列，并覆盖相同物理时间。时间起点、长度、复增益/相位/CFO 应对齐到足以训练；Hybrid Loss 只能容忍残余偏差，不能修复错 packet 或错 symbol。

论文正文没有明确说明 `signalout_*` GT 是理想发射基带还是高 SNR 实采 clean IQ。根据 `signalout` 命名和 `packet_id % 100` 配对规则，较强推断是作者循环使用约 100 个预生成 clean references 对应 10,000 次 OTA receptions；必须将其标为代码推断，不能写成论文已确认事实。

自建 noisy-IQ 数据最稳妥的 map：

```text
clean_2m = 一条已同步的高 SNR clean capture
y = clean_2m[::2]

noisy_2m = clean_2m + 独立噪声 realization
x = noisy_2m[::8]
```

先按原始 `clean_capture_id` 划分 train/test，再分别加噪。不能让同一个 clean capture 的 -10 dB 版本进训练、-15 dB 版本进测试；它们共享 payload、CFO、STO、相位、信道和完全相同 GT，会造成数据泄漏。更严格实验可按 payload、session、位置或设备分组。

建议自建 manifest：

```text
rx_path,ref_path,snr_db,packet_id,capture_id,session_id
```

不要继续依赖作者文件名 `%100` 的隐式映射。

## 6. Loss 与两阶段训练代码现状

Synthetic `model0v0` 默认使用 MSE。

OTA checkpoint 名称中的：

```text
model0v0lopenaltyhl
        |         |
        |         +-- HybridDenoiserLoss
        +------------ CNN 参数 L1/Lasso 正则
```

Hybrid loss：

```text
L = lambda_time * L1(pred_IQ, target_IQ)
  + lambda_freq * L1(|FFT(pred)|, |FFT(target)|)
```

时域 L1 抵抗 impulsive/non-Gaussian outliers；频域幅值 L1 对全局相位和理想循环时移更宽容，但并不严格对 CFO 不变。论文正文报告 `lambda_freq=0.5`，公开代码默认 `0.1`，复现时必须记录所选值。

当前公开 OTA 训练路径不能直接运行：

1. `nn.py` 没有导入 `OTALoRaDataset`。
2. `dataset.py` 缺少 `filter_files_by_snr`。
3. `dataset.py` 缺少 `get_reproducible_split`。
4. `dataset.py` 使用 `os.path` 但没有 `import os`。
5. `DATA_DIRECTORY` 硬编码为作者环境 `deepstudy/nn/data`。
6. `--ota` 只切换 dataset，并不会自动加载 synthetic checkpoint。
7. 训练脚本只按完整生成的 checkpoint 名字自动续训，没有显式 `--pretrained`。
8. OTA 分支只允许 SF12；当前 `nn.py` 也没有独立 validation/test loop。

因此，恢复 OTA 微调前应先实现 manifest loader、明确 synthetic->OTA 权重初始化和验证集入口，而不是仅下载数据后直接执行 `--ota`。

## 9. 降低巨大输入的可选路线

优先级建议：

### 9.1 保留 model0，窗口化训练/流式推理

这是最小风险路线。现有 weak-decoder frontend 已实现 overlap-cropped chunked inference，可复用同一边界逻辑。Synthetic MSE 预训练可直接采用配对窗口；OTA Hybrid FFT loss 若改为窗口级，需要重新评估其含义。

### 9.2 使用仓库已有 `SimpleComplexCNN1`

`model1` 在低采样率 `L` 上运行 CNN，输出 OSF 个 phase residual，再 reshape 为 `[B,2,4L]`。相比 model0 在 `4L` 上保存多层中间 activation，显存显著更低，但没有公开 checkpoint，需要重新训练并与 model0 做性能消融。

### 9.3 LoRa symbol/sub-chirp 网络

SF12/BW125 下，一个 symbol 是 8,192 个 250 kSPS 输入 samples、32,768 个 1 MSPS 输出 samples。可按同步后的 symbol 或 sub-chirp 训练，显存更低，但会引入对 SF/BW 和 symbol boundary 的依赖，不再是通用 raw-IQ frontend。

不建议对几十万 samples 直接使用全局 Transformer attention。

## 10. 正式五臂实验的阻塞点

1. 当前 Branch4 synchronized captures 是 SF10/BW125/500 kSPS，不是 native 1 MSPS，不能作为 arm E。
2. RF-SR 公布权重是 SF12/BW125。用在 SF10 必须标记为 domain transfer，不能当论文同域结论。
3. 旧 `gr-lora_sdr/data/USRP_IQ` SF12 文件缺少足够明确的采样率/配对元数据，不能直接认定为 matched native-high reference。
4. 正式实验需要独立 1 MSPS clean capture、对应 off-packet noise-only IQ、固定 payload 和可审计同步元数据。
5. 每个 arm 必须从对应转换后的 off-packet noise 估计 branch covariance，不能复用 native-high covariance 给 RF-SR 输出。
6. 目前只有 one-symbol probe 和 frontend tests，没有正式 PER/SER 曲线，不能声称 RF-SR+Savaux 已提升或已失败。

## 11. 下一步建议顺序

1. **先决定训练工程路线。** 首选为 model0 窗口训练；若要严格保持作者 full-packet loss，则实现 batch1+accumulation5+AMP 和低内存 dataset。
2. **实现 manifest-based paired dataset。** 显式保存 rx/ref/snr/capture/session，完成 complex64/sc16 转换、长度检查和 group split。
3. **加入显式 `--pretrained` 和 validation loader。** 使 synthetic->OTA 两阶段训练可复现，而不是依赖 checkpoint 文件名碰撞。
4. **采集 SF12/BW125、native 1 MSPS 数据。** 同时保存 noise-only windows；clean GT 与 noisy input 必须可配对。
5. **跑五臂 paired experiment。** 先 smoke，再扩 SNR/seed；报告 PER、bin-PER、SER、GT/false peak ratio 和 branch correlation/effective rank。
6. **只在 B vs D 显示稳定 paired gain 后讨论 Savaux 新增观测。** 若 D≈C，则增益主要来自 CNN 去噪；若 D>C 且 branch covariance 显示新增 rank，才支持组合火花。
