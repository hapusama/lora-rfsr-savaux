### GLS 的当前统一理解

对某个候选 FFT bin，将多条 pattern/branch 的复观测堆成：

```text
y = a x + eta,    E[eta eta^H] = C
```

GLS 复幅度估计为：

```text
x_hat = (a^H C^-1 y) / (a^H C^-1 a)
```

用于候选 bin 排序的归一化检测功率为：

```text
score = |a^H C^-1 y|^2 / (a^H C^-1 a)
```

这和“先用 `C^-1/2` 白化，再做最大输出 SNR 匹配合并”是同一个结果。
`C^-1` 本身只描述如何抑制相关/有色噪声；最终权重还必须包含信号响应方向 `a`。

非均匀采样的离线目标，是从候选 pattern 中选择使

```text
J(I) = a_I^H C_I^-1 a_I
```

尽量大的子集。当前文档示例是从约 96 个软件 pattern 中选 8 个。pattern 不是新的
物理天线或独立副本，而是对同一份 OSR=4 IQ 的不同软件投影；AWGN 下的有效自由度
不会因为无限增加 pattern 而超过物理 OSR。

当前 `os_lora` 下已有大量仿真/评估实现，但尚未确认已经把真实 `low1/low2/low3`
完整接入成“一条命令完成同步、GLS 判决和 SER 汇总”的正式链。不要把仿真结果当作
真实环境验证结果。

固定 FCnt 的实现位置：

```c
// apps/main.c
static const uint32_t UpLinkCounter = 1;
```

组帧时直接写入该常量的低 16 bit，没有自增：

```c
LoRaMacBuffer[pktHeaderLen++] = UpLinkCounter & 0xFF;
LoRaMacBuffer[pktHeaderLen++] = (UpLinkCounter >> 8) & 0xFF;
```

应用 payload 由 `PrepareTxFrame()` 每次确定性生成：

```c
AppTxDataBuffer[i] = '0' + i;   // i = 0..19，字节值 0x30..0x43
```

因此后半段不全是可打印数字：`0x3A..0x40` 会显示为 `:;<=>?@`，随后是 `ABC`。
这可以解释过去按字符串查看 payload 时“内容很怪”但实际字节并未随机变化的现象。

自定义帧中的 MIC 也固定为 `0x12345678`。在 payload、FCnt、头字段和 PHY 配置均不变
时，每次发射的编码 LoRa symbol 序列应保持不变，因而一份可靠 high-SNR FFT-bin GT
可以复用于后续多份低 SNR 采集。

若以后改变 payload、FCnt、DevAddr、FPort、FCtrl/FOpts、MIC、payload 长度、SF、BW、
CR、header/CRC/LDRO 中任一项，必须重新建立 GT，并另建数据集目录，不能混入当前
`branch4_fixed`。

## 5. 当前离线解码链结构

说明文档：

```text

```

当前可信链路分为两个命令阶段，不会自动一口气跑完：

```text
raw complex64 IQ
  -> preamble detector
  -> event start refinement
  -> sync word + SFD frame locator
  -> gr-lora-style CFO/STO/SFO frame sync
  -> sync.csv
  -> explicit-header-first ordinary FFT demod
  -> fft_symbols.csv / fft_frames.csv
```

### 第一阶段：IQ 到 frame sync

从 `weakPacket_decoding` 目录运行：

```powershell
python -m weak_decoder.run_iq_frontend `
  --input "USRP_collector\data\branch4_fixed\high_snr\sf10_bw125_fs500_pre32_sw34_r001.bin" `
  --output "data\frontend\sf10_bw125_fs500_pre32_sw34_r001_sync.csv" `
  --sf 10 `
  --bw 125000 `
  --samp-rate 500000 `
  --center-freq 487700000 `
  --sync-word 0x34 `
  --preamble-len 32 `
  --win-chirps 4
```

调用关系：

```text
weak_decoder/run_iq_frontend.py
  -> scripts/run_weak_sync_chain.py
       -> weak_decoder.preamble_detector.detect_preamble_runs()
       -> align_event_start()
       -> weak_decoder.frame_locator.locate_frame_from_event()
       -> weak_decoder.grlora_frame_sync.run_grlora_frame_sync_validation()
       -> sync CSV
```

#### 前导码检测细节

`--preamble-len 32` 是发射端前导 upchirp 总数；`--win-chirps 4` 是检测窗口长度，
两者不能混为一谈。

当前每个 chirp：

```text
2^SF * Fs / BW = 1024 * 4 = 4096 samples
```

每个检测窗口为 4 个 chirp，即 16384 samples。每个 chirp 分别 dechirp + FFT，随后
逐 bin 做非相干功率累加：

```text
E[k] = sum_(m=0..3) |FFT_m[k]|^2
```

滑窗默认每次前进一个 chirp。若未显式给出门限，连续稳定窗口数取：

```text
preamble_len - win_chirps + 1 = 32 - 4 + 1 = 29
```

峰值 bin 默认允许约 ±2 bin 的循环距离。粗检测目前没有实质性的绝对能量门限，
主要依赖 peak-bin 连续稳定，因此可能产生稳定窄带噪声候选；后续 sync word/SFD 和
frame sync 继续过滤。`align_event_start()` 细化阶段也使用 4-chirp 功率累加。

### 第二阶段：frame sync 到普通 FFT demod

```powershell
python scripts\run_header_first_demod.py `
  --input "USRP_collector\data\branch4_fixed\high_snr\sf10_bw125_fs500_pre32_sw34_r001.bin" `
  --sync-csv "data\frontend\sf10_bw125_fs500_pre32_sw34_r001_sync.csv" `
  --output "data\frontend\sf10_bw125_fs500_pre32_sw34_r001_fft_symbols.csv" `
  --frames-output "data\frontend\sf10_bw125_fs500_pre32_sw34_r001_fft_frames.csv" `
  --consistency-output "data\frontend\sf10_bw125_fs500_pre32_sw34_r001_payload_consistency.csv" `
  --sf 10 `
  --bw 125000 `
  --samp-rate 500000 `
  --frame-filter framesync-valid
```

该阶段先解调 8 个 explicit-header symbols，解析 header 得到 payload symbol 数，再导出
完整 8 header + 49 payload 共 57 个 FFT-bin。当前可信边界是“同步和 FFT-bin 导出”；
payload bytes、dewhitening 和最终 CRC 还没有作为默认链完成端到端验证。


GT 中前 8 行是 PHY header，后 49 行是 encoded payload symbols。做 FFT-bin SER 必须比较：

```text
低 SNR 解调 CSV: raw_fft_bin
GT CSV:          groundtruth_fft_bin
对齐键:          frame_symbol_index（0..56）
```

不要把 `groundtruth_symbol` 当 FFT 数组下标。payload 的 gr-lora 映射约定为：

```text
groundtruth_symbol = (groundtruth_fft_bin - 1) mod 1024
```

只要固定发射帧和 PHY 配置不变，这一份 GT 可以复用于 `low1/low2/low3` 以及后续所有
同配置低 SNR 采集，不需要每个 `.bin` 重新生成 GT。

## 7. 低 SNR 评估口径

不能只汇报“成功同步帧中的 SER”，否则漏检的包会从统计中消失。至少分别报告：

1. 前导码检测数 / 预计发包数；
2. `grlora_framesync_valid` 数量和比例；
3. 成功同步帧上的 FFT-bin SER；
4. 一帧任一 symbol 出错即失败的 FFT-bin frame error rate；
5. false event / false sync 情况。

当前 3 s 发一次包，若保存时长为 120 s，理论上约有 40 次发射，但实际数量需要结合
采集起止时刻和检测结果核对，不能机械假定恰好 40。

当前只能严谨地表述为“FFT-bin 解调正确率”，不能表述为完整 LoRa payload/CRC
端到端正确率。
