## 1. Corrected Objective

The intended decoder is **not** a byte/payload candidate enumerator.

The intended decoder is a **symbol-level two-stage FFT-bin selector**:

```text
low-SNR payload FFT evidence
  -> stage 1: oversampled / multi-offset FFT screening
  -> lock high-confidence symbols directly as Top-1
  -> keep low-confidence symbols as small Top-L candidate sets, default L=8
  -> use locked symbols to build a stronger packet-local phase line
  -> stage 2: choose the best bin for low-confidence symbols from their Top-L sets
            using phase-line smoothness and bounded amplitude/phase scoring
  -> only after symbol bins are selected, run the normal LoRa PHY decode / CRC check
```

Hard constraints:

- No known payload bytes.
- No counter/template/application prior.
- No cross-packet joint prior.
- No retransmission combining.
- Do not enumerate payload bytes as the main second-stage search.
- CRC may be used as final validation, but should not be the source of a payload-byte prior.

## 4. Intended Two-Stage Algorithm

### Stage 1 - Oversampled FFT screening and confident symbol locking

For each payload symbol `k`:

1. Extract center FFT spectrum:

```text
Z_center[k, b]
```

2. Extract multi-offset / oversampled evidence:

```text
E[k, b] = sum_o |Z_o[k,b]|^2 / max_b |Z_o[k,b]|^2
```

3. Rank bins by multi-offset evidence, optionally with light phase-gated bonus.

4. Compute confidence metrics for the Top-1 bin:

Suggested metrics:

```text
top1_margin_db       = 10log10(E[top1] / E[top2])
top1_peak_ratio      = E[top1] / sum_b E[b] or E[top1] / median(E)
multi_offset_quality = stability of the peak across offsets
phase_residual       = wrap(angle(Z_center[top1]) - theta_prelim[k])
phase_score          = 0.5 + 0.5*cos(phase_residual)
```

5. Partition symbols:

```text
locked symbols:
  confidence >= threshold
  -> commit Top-1 bin immediately

uncertain symbols:
  confidence < threshold
  -> keep candidate set C_k = Top-8 bins
```

Important: locked symbols are not given a candidate set in the main search. This is where we save complexity and avoid wasting the reliable first-stage result.

### Stage 1.5 - Build packet-local phase line

Use locked symbols to fit a stronger packet-local phase line:

```text
theta_k = a * abs_symbol_index_k + c
```

Fit from:

```text
(abs_symbol_index_k, angle(Z_center[k, locked_bin_k]))
```

Use robust fitting / trimming. Header or preamble anchors may be used as fallback, but the historical experiments show header-to-payload slope mismatch, so payload locked symbols should dominate when available.

Track line quality:

```text
anchor_count
line_rmse_pi
line_r2
residual_std_pi
```

If quality is poor, fall back to multi-offset Top-1 or keep a larger candidate set. Do not let random phase-only bins dominate.

### Stage 2 - Symbol-level phase-smooth candidate selection

For each uncertain symbol `k`, candidate set:

```text
C_k = {b_k,1, ..., b_k,8}
```

Candidate point:

```text
z_k(b) = Z_center[k, b]
r_k(b) = wrap(angle(z_k(b)) - theta_k)
phase_score_k(b) = 0.5 + 0.5*cos(r_k(b))
amp_score_k(b) = E[k,b] / max_b E[k,b]
```

Local candidate score:

```text
local_score_k(b)
  = w_phase * phase_score_k(b)
  + w_amp   * amp_score_k(b)
  + optional profile term
```

But the main second-stage idea should be trajectory smoothness across uncertain symbols plus locked anchors.

For a candidate assignment `A` over uncertain symbols:

```text
A = { b_k : k in uncertain_symbols }
```

Build selected phase points:

```text
locked points:
  (abs_k, angle(Z_center[k, locked_bin_k]))

candidate points:
  (abs_k, angle(Z_center[k, b_k]))
```

Fit a line to all selected points and compute:

```text
line_score(A) = exp(-(line_rmse_pi(A) / 0.30)^2)
```

Bounded trajectory score:

```text
trajectory_score(A)
  = 0.25 * mean(phase_score_k(b_k))
  + 0.50 * line_score(A)
  + 0.20 * mean(amp_score_k(b_k))
  + 0.05 * mean(profile_score_k(b_k))
```

This formula is inspired by `_score_payload_symbol_prior_candidate()`, but the candidates are **symbol bin assignments**, not payload-byte candidates.

### Search strategy

Avoid exhaustive `8^N` search when many symbols are uncertain.

Recommended:

```text
beam over uncertain symbols
  state = selected bins so far + current fitted line / score
  expand each low-confidence symbol by Top-8 candidate bins
  keep beam_width states
```

Ordering uncertain symbols:

```text
highest confidence first
or
smallest phase ambiguity first
```

The beam score should combine:

```text
sum local_score
line_score over locked + selected candidate points
penalty for large phase jumps / poor line quality
```

After selecting bins for all uncertain symbols:

```text
full_raw_bin_sequence =
  locked top1 bins
  + selected uncertain bins
```

Then run normal LoRa payload decode and CRC.

## 5. Why This Matches the Experimental Observation

The historical figures show that after removing offsets, correct-bin phases preserve a usable packet-local structure even at low SNR.

The first-stage phase-gated Top-L recall showed that phase as a tiny per-bin bonus has limited incremental gain over strong multi-offset evidence.

Therefore, phase should not only be used as a small bonus before decoding. It should be used in stage 2 as a **trajectory smoothness constraint** over the ambiguous symbols, while high-confidence symbols are locked and used as anchors.

That is the main research point:

```text
oversampled FFT finds a small candidate set;
phase-line smoothness decides among candidates when energy alone is ambiguous.
```

## 9. Current Implementation Status

Implemented on 2026-06-16:

```text
weak_decoder/symbol_phase_two_stage.py
scripts/experiments/run_symbol_phase_two_stage.py
notes/plans/SYMBOL_PHASE_TWO_STAGE_RESULTS_2026-06-16.md
```

The current implementation follows the corrected symbol-level design:

```text
multi-offset FFT evidence
  -> lock high-confidence payload symbols as Top-1
  -> keep Top-8 only for low-confidence symbols
  -> fit a packet-local phase line from locked symbols
  -> use phase consistency only to override ambiguous Top-1 bins
  -> run LoRa hard decode and CRC after symbol-bin selection
```

It does **not** enumerate payload bytes and does **not** use CRC, payload
templates, counters, or cross-packet evidence during peak selection.

The first naive phase trajectory beam was too aggressive: it could select a
smooth but wrong phase track and degrade the strong multi-offset Top-1 baseline.
The current default is therefore conservative.  Top-1 remains the default answer
for uncertain symbols; an alternative Top-8 candidate may replace it only when
the locked-symbol phase line is reliable and the candidate has both a clear
phase gain and a small multi-offset energy drop.

Default conservative override gates:

```text
phase_override_min_line_anchors = 8
phase_override_max_line_rmse_pi = 0.25
phase_override_min_gain = 0.15
phase_override_max_drop_db = 0.60
phase_override_score_margin = 0.06
local_score = 0.20 * phase_score + 0.80 * amp_score
```
